# 네 메인 기능 공부 지도

## BEST11

- 주소: `/player/best11/`
- 서버: `player/views.py` → `services.py` → `scoring.py`
- 연구실: `player/lab/urls.py` → `views.py` → `service.py`
- 케미: `player/lab/chemistry.py`
- 화면: `player/templates/player/best11.html`
- 조작: `player/static/player/best11_edit.js`

먼저 `scoring.GROUPS` 하나와 `metric_weights()`를 읽고, `Normalizer.unit()`을 따라갑니다. 공식 랭킹은 600분 자격, 점수 비교 기준과 포메이션 후보는 450분이라는 차이를 유지합니다.

## 승부예측

- 팀 기록 기본 예측: `/team/predict/` → `team/prediction_views.py` → `match_prediction.py`
- 라인업 실험: `/team/simulate/` → `simulation_views.py` → `lineup_simulation.py`
- 선수 점수: `player_score_context()` → `player/lab/service.py`
- 공격/수비: `team_strength()` → `player_probabilities()`
- 혼합 결과: `simulate()`에서 팀 확률과 선수 확률을 혼합
- 화면 조작: `team/static/team/lineup_simulation.js`

`PART_WEIGHTS`, `MAX_PROBABILITY_CHANGE`처럼 예전 방식의 이름도 남아 있습니다. 상수가 보인다는 이유로 현재 최종 확률에 적용된다고 판단하지 말고 `simulate()`가 실제로 호출하는 함수를 따라가세요. 현재 기본 혼합은 팀 70%, 선수 30%지만 관리자 설정에 따라 달라질 수 있습니다. 학습으로 찾은 최적 비중은 아닙니다.

## GPS 모의경기

- 데모 주소: `/player/tracking-demo/`
- 데모 화면: `player/tracking_demo_views.py`
- 좌표 생성: `simulation/generator.py`
- 기본 검사: `validate_tracking_demo.py`
- 거리/속도: `simulation/tracking_metrics.py`
- 위치/지역: `simulation/tracking_spatial.py`
- 패스/가로채기: `simulation/event_metrics.py`
- 저장: `simulation/management/commands/summarize_player_tracking.py`
- 선수 기록 조회: `player/simulation_records.py`, `simulation_summary.py`

```text
가상 JSON → 검증 → 프레임 두 개씩 비교 → 거리·속도 계산
         → 선수별 합산 → 명령어에서 DB 저장 → 선수 화면
```

`extract_player_tracking()`은 계산만 하고 `update_or_create()`가 DB에 씁니다. 원본 명단과 당시 좌표는 `SimulationRun.document`에 보관합니다. 실제 선수의 GPS 측정값이 아니라 더미이며 현재 확률에 자동 반영하지 않습니다.

## 축구게임

- 주소: `/soccer_game/game/`
- 진입: `soccer_game/urls.py` → `views.game()`
- 템플릿 후보: `soccer_game.html`, 없으면 `soccer_game/pending.html`

확인한 GitHub 6안은 root `soccer_game` 폴더와 동일한 통합 엔진 상태가 아닙니다. 이번 정리는 6안의 기존 게임 코드와 경로를 보존했습니다. 브라우저에서 현재 진입 화면은 확인했지만 다른 폴더의 새 엔진을 병합한 것은 아닙니다. 실제로 어떤 HTML이 선택되는지와 Network의 정적 파일 요청을 먼저 확인하세요. PPT의 최신 게임 보고서가 현재 GitHub 6안 소스에 모두 반영됐다고 가정하면 안 됩니다.

## 지원 기능

- `manager`: 업로드 검토·적용, 백업, 가중치 설정
- `board`: 회원·게시글·댓글·신고
- `home`: 메인 페이지와 메뉴
- `project01`: 전체 주소와 Django 설정

나머지 파일의 함수·클래스 목록은 전체 파일 지도에서 찾습니다. 기존 `CLAUDE.md`에는 과거 계산 요약도 있으므로 현재 실행 코드를 우선해서 읽으세요.
