# 문법과 데이터 흐름

## 사전: dictionary는 이름표가 붙은 보관함

```python
result = get_filtered_best11(team_id=team_id, formation=formation)
selected_team_id = result['team_id']
```

`result`는 모델이나 예약어가 아닙니다. 함수가 돌려준 사전(dict)에 붙인 변수 이름입니다. `get_filtered_best11()` 맨 아래 `return {...}`에 `'team_id'`라는 키가 있습니다. `result['team_id']`는 그 칸의 값을 꺼냅니다.

```python
result = {'team_id': 10, 'selected_count': 11}
print(result['team_id'])  # 설명용 예: 10
```

구단 ID 10이 어느 팀인지는 실제 DB로 확인해야 합니다. 예제의 숫자를 모든 데이터에 고정하지 마세요.

## filter와 first

- filter는 ‘조건으로 거르다’라는 뜻입니다. `.filter(id=selected_team_id)`는 해당 ID의 구단만 남깁니다.
- first는 ‘첫 번째’입니다. `.first()`는 첫 객체 하나를 돌려주고 없으면 `None`입니다.
- `if selected_team_id:`는 비어 있거나 0 같은 값이 아닌지 확인합니다.

## 함수와 return

함수(function)는 작업에 이름을 붙인 묶음입니다. `def`로 만들고 `return`으로 결과를 돌려줍니다. `return` 이후 그 함수의 실행은 끝납니다.

```python
def per90(value, minutes):
    if minutes <= 0:
        return 0.0
    return value / minutes * 90
```

실제 `services.per90`에는 숫자 변환도 있습니다. `scoring._p90`은 계산 불가 시 `None`을 돌려주므로 둘은 무조건 합치면 안 됩니다.

## round

`round(number, 2)`는 소수점 둘째 자리까지 반올림합니다. `2`는 출전시간도, 곱하는 숫자도 아닙니다. 중간 단계에서 반올림을 추가하면 최종 점수와 순위가 바뀔 수 있어 기존 위치를 유지했습니다.

## for와 사전

```python
position_count = {'FW': 0, 'MF': 0, 'DF': 0, 'GK': 0}
for stats in candidates:
    position = (stats.player.position or '').strip().upper()
    if position in position_count:
        position_count[position] += 1
```

`for`는 목록에서 하나씩 꺼내 반복합니다. `strip()`은 양끝 공백 제거, `upper()`는 대문자 변환입니다. `+= 1`은 기존 숫자에 1을 더해 저장한다는 뜻입니다.

## 목록 화면의 흐름

```text
/player/plist/?team=10&position=FW
  → project01/urls.py
  → player/urls.py의 plist 경로
  → player/views.py의 plist(request)
  → request.GET에서 team, position 읽기
  → Player.objects.filter(...)로 조회
  → attach_simulation_summaries(...)로 더미 요약 연결
  → context 사전
  → player/templates/plist.html
```

`context`는 화면에 보낼 이름표 묶음입니다. Python에서 `'list': players`로 보낸 내용이 Template의 반복문에 사용됩니다.

## BEST11의 흐름

```text
/player/best11/
  → views.best11
  → services.get_filtered_best11
  → 450분 이상 리그 전체 후보
  → scoring.metric_values로 선수 지표 계산
  → scoring.Normalizer로 같은 포지션 기준 정규화
  → 가중치 × 항목 점수 합산
  → 선택 구단 필터 → 포메이션 인원 선택
  → result 사전 → context → best11.html
```

내 설정과 케미를 다루는 연구실은 별도 JSON API와 `player/lab/service.py`를 사용합니다. 모든 화면이 View 하나만 거치는 것은 아닙니다.

## JSON과 AJAX

JSON은 사전/목록 같은 데이터를 주고받는 글자 형식입니다. AJAX는 화면 전체를 다시 열지 않고 서버에서 계산 결과를 받아 일부 화면을 바꾸는 방식입니다.

```text
버튼 → JavaScript fetch → lab/urls.py → lab/views.py
    → lab/service.py → JSON 응답 → 카드·그래프 변경
```
