# 수정·추가 연습

## 연습 1: 가중치를 바꾸기 전에 계산 읽기

`player/scoring.py`의 `GROUPS['FW']`를 찾습니다.

```python
('finishing', '득점력', 45, ['goals90', 'sot90', 'shots90', 'shot_acc', 'conv', 'box'])
```

각 칸은 범주 키, 화면 이름, 기본 비중, 평가 지표 목록입니다. 45를 6개에 나누면 한 항목 비중은 7.5입니다. 정규화 값이 0.5면 3.75점 기여합니다.

`metric_weights()`를 따라가면 전체 비중 합을 100으로 환산하는 코드도 볼 수 있습니다. 관리자 저장값이 있으면 코드의 기본값보다 먼저 적용될 수 있습니다. 따라서 숫자만 바꿨는데 화면이 같다면 `manager/config.py`의 저장 설정 적용도 확인하세요.

가중치 변경은 결과를 바꾸는 실험입니다. 이번 작업본에서는 비중을 바꾸지 않았습니다. 변경할 경우 실습 복사본에서 선수 점수와 순위를 전후로 비교하세요.

## 연습 2: 기존 컬럼으로 새 평가 지표 만들기

DB 컬럼을 추가하지 않는 예제입니다. `METRIC_DEFS`에서 이미 있는 `fouls` 기록을 읽을 수 있습니다.

```python
# METRIC_DEFS 안에 추가하는 예시입니다. 지금 작업본에는 적용하지 않았습니다.
'fouls90': (
    '파울',
    lambda stats, virtual_data: _p90(stats.fouls, stats.minutes),
    False,   # 낮을수록 좋음
    PER90,   # 90분당 기록
    'fouls', # 시즌 합계 원본 필드
    False,   # 실제 기록; 가상 표시 아님
),
```

- `lambda`는 이름을 따로 붙이지 않은 짧은 함수입니다. 두 입력을 받고 `_p90(...)`의 값을 돌려줍니다.
- 정의만 추가하면 점수에 반영되지 않습니다. 원하는 포지션의 `GROUPS`에 `'fouls90'`도 넣어야 합니다.
- 그룹에 넣으면 같은 범주 안의 다른 항목 비중도 바뀝니다. 점수·순위가 달라질 수 있습니다.
- 자동으로 새 DB 컬럼이나 HTML 표가 생기는 것은 아닙니다. 보고서·그래프·관리 화면은 참조 지표와 표시 구성을 확인해야 합니다.
- 현재 DF의 `disc90`에 이미 파울이 포함돼 있어 함께 쓰면 중복 평가할 수 있습니다. 실습에서 의미를 먼저 결정하세요.
- 여러 포지션에 같은 지표를 넣어 비교하고 싶다면 각 포지션의 그룹에도 명시해야 합니다.

이번 예제는 기존 DB 필드를 읽으므로 `makemigrations`가 필요 없습니다.

## 연습 3: 정말 새로운 DB 컬럼 추가하기

새로운 심박수 같은 자료는 계산식 하나만 추가한다고 생기지 않습니다. 측정 자료와 단위가 먼저 필요합니다.

1. 시즌 값인지 경기별 값인지 결정합니다. GPS 경기별 값은 `PlayerStats`가 아니라 `SimulationPlayerTracking` 등 별도 기록 모델을 확인합니다.
2. 실측과 가상을 구분하고 `None`과 0의 뜻을 정합니다.
3. 대상 모델에 필드를 추가합니다. 과거 행을 어떻게 채울지도 정합니다.
4. 복사본에서 `python manage.py makemigrations`로 변경 내용을 확인합니다.
5. `python manage.py migrate`로 복사본 DB에 반영합니다.
6. 데이터 읽기/집계/저장 코드를 연결합니다.
7. View와 Template에서 값을 표시합니다.
8. 점수에 사용할 경우에만 평가 정의·범주·누락값·방향을 정하고 점수 변화를 검증합니다.

이 절차는 학습 안내입니다. 이번 작업은 모델이나 migration을 변경하지 않았습니다.

## 연습 4: GPS 기준을 찾기

`simulation/tracking_metrics.py`의 `PARAMETERS`에서 고속 이동 19.8, 스프린트 25.2km/h, 최소 1초를 확인합니다. 기준을 바꾸면 지표가 달라지는 기능 변경입니다. 기존 기록을 다시 집계할 때는 계산 버전과 저장 명령의 `update_or_create` 조건도 확인해야 합니다.

`TRACKING_VERSION`의 철자는 호출하는 명령어와 연결돼 있으므로 함부로 이름을 바꾸지 않습니다. 버전 값을 새로 정하면 기존 행을 갱신하는지 새 행을 만드는지 먼저 확인합니다.
