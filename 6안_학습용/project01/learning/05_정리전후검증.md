# 전체 코드 정리 결과와 검증

## 범위

Python 141개, JavaScript 20개, CSS 11개, HTML 33개를 정리했습니다. JavaScript/CSS 중 11개는 HTML에서 분리한 새 파일입니다. 파일별 안내는 205개입니다.

- Python은 줄바꿈·조건문·사전 표현·들여쓰기를 통일하고 역할 주석을 넣었습니다.
- 공통 점수와 BEST11은 1차 정리를 유지했습니다.
- 연구실 `base_weights`, `build_weights`, `_shrunk`, `ability_scores`를 단계별로 풀었습니다.
- 예측 `poisson_probabilities`, 라인업의 `player_score_context`, `slots`도 단계별로 풀었습니다.
- HTML에서 독립 CSS/JS만 분리했습니다. Django 변수, 템플릿 조건, 상대 이미지 URL, 특수 script 속성이 있는 부분은 무리하게 옮기지 않았습니다.
- JavaScript 문법 구조를 비교했고 CSS 선택자·값·미디어 조건·규칙 순서를 유지했습니다.
- Python 자동 서식 정리는 처리 구조를 비교했습니다. 직접 풀어 쓴 계산은 결과 비교로 확인했습니다.

## 유지한 것

원본 DB 파일, 모델 필드·관계·제약조건, migration 24개, 공개 함수 이름·인자·반환 키·URL·기본 가중치·사진/데이터 파일입니다. 모델 파일은 주석과 서식만 변경했으며 DB 영향과 새 migration은 없습니다.

과거 참고 Python 17개와 `.site_nav_backups`는 기존 자료로 보존했습니다. 참고 파일 `기본소스모음/soccer_전역활동부여.py`의 기존 문법 오류를 현재 서비스 오류처럼 고치지 않았습니다.

## 화면과 연결 비교

원본과 정리본을 각각 DB 복사본으로 실행해 같은 브라우저 조건에서 확인했습니다.

- 메인, 선수 목록, 선수 상세, BEST11, 기본 예측, GPS, 관리자 기준, 업로드, 게시판, 게임: 10개 화면의 상태·제목·주요 요소 위치/크기/색상 일치
- BEST11 자동 채우기 → 라인업 예측 이동 성공
- 기록만 / 가중치 포함 모드 변경 성공, 전환 결과 일치
- 확인한 브라우저 흐름에서 JavaScript 오류와 HTTP 오류 없음
- 계산 비교와 브라우저 검증은 복사 DB만 사용했고 원본 DB는 보존

UI 비교는 주요 요소 기준입니다. 모든 픽셀·모든 포메이션·모든 버튼 조합·모든 축구 규정의 완전 검증은 아닙니다. 외부 CDN 상황의 영향을 줄이기 위해 브라우저 비교에서는 외부 요청을 양쪽 모두 차단했습니다.
